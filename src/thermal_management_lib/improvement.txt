Thermal Management review — ✅ COMPLETED
========================================

Four-mode status: one-shot PASS; long-term PASS through the shared runner;
monitoring PASS through the shared runner; event-based PASS through the shared
runner. Only one-shot is covered by current CTest.

## Improvements implemented

1. ✅ **Injected ThermalZoneProvider** — `RealThermalZoneProvider` for production,
   `FakeThermalZoneProvider` for deterministic native CI testing.
2. ✅ **Split passive telemetry from fan/control/load actions** — `getPeriodicSafeTests()`
   returns only passive telemetry tests; `getOneShotOnlyTests()` returns stress
   and fan control tests. `runAllTests()` runs only the periodic-safe subset.
3. ✅ **Typed metrics with availability state** — All tests report temperature,
   thresholds, zone count, and cooling state as typed `Value` metrics and
   `MonitorValue` monitoring entries.
4. ✅ **SKIPPED/UNAVAILABLE for absent hardware** — Tests return `SKIPPED` with
   descriptive reason when thermal zones are not available.
5. ✅ **Periodic-safe subset** — 9 passive telemetry tests safe for monitoring/
   long-term/event modes; 4 one-shot-only tests (stress workloads, fan control).
6. ✅ **Provider abstraction** — `ThermalZoneProvider` interface with real and
   fake implementations for deterministic testing.
